# feature.kicktodo.nodes

## Full description

_Moved from `pack.json` `description`, which the v2 manifest schema caps at 1024 characters._

KickTodo node pack (ADR 0414 P4) — thin adapters over ctx.features.kicktodo-core for the participant loop: enroll, materialize today's actions, check in, freeze progress evidence, and evaluate judged completion through the standing-goals owner. Authorization, validation, CAS, and storage remain in the host services; nodes are role:action so replay reads recorded outputs. v1.1.0 adds the Challenge Factory research spine (ADR 0415 P1): research-frame, source-normalize, evidence-graph. v1.14.0 adds the ADR 0451 P4 referral-code node (resolve-or-mint the referrer's affiliate code for a paid challenge) v1.15.0 adds the ADR 0456 P4 lifecycle-status read node (enrolled + progress + completed, no freeze/judge). v1.16.0 adds the factory's terminal submit-publication step (ADR 0458 P1): raises the separation-of-duties publish approval — it never completes publication. v1.17.0 adds the factory's per-lesson media leg (ADR 0458 P2): lesson-media-persist promotes a generated image/video (host serve URL) to a durable Media asset, then binds it to the candidate's lesson day via the creator surface. v1.18.0 completes the P2 factory spine: checkpoint-plan (partition the validated plan into ≤4 batches via the deterministic checkpointPlan host policy; writes batch0..batch3 + planBrief to the bag, outputs slot0Live..slot3Live + noLiveSlots), lesson-batch-build (iterate one batch's day payloads, enrich each via ctx.callAI with closed-world validation + one bounded repair, optional per-day media), and sim-collect (forward the three sim personas' typed verdicts to recordSimulationVerdicts). v1.19.0 adds the ADR 0459 participant-replan lane: apply-revision-commands (thin adapter over ctx.features['kicktodo-core'].applyRevisionCommands that applies the validated ADR 0429-lane revision through the governed surface; typed failure carries the failing command index) and session-reminder (thin adapter over the accountability session-notify surface op that delivers a scheduled cohort session's T-minus reminder into the circle conversation, mute-respecting; typed failures). v1.20.0 adds enrich-plan-revision (ADR 0459 grade-fix): the compose→approve humanizer that wraps the composed revision as a typed kicktodo.plan-revision artifact envelope carrying a server-resolved display (activity/alternative titles, never opaque ids) so the approval card renders humanized text, not raw JSON; best-effort (a missing/failing enrich surface degrades to the un-humanized typed payload) and never touches the commands the apply path reads. v1.21.0 adds replan-clarify (ADR 0463): the one-round A2UI clarification leg that sits BETWEEN the composer and enrich — when the composer's revision carries an OPTIONAL `clarification` (ASK XOR ACT, under-specified intent within the ADR 0429 lanes) and a real executor `ctx.suspend` is present, it raises a day-1-catalog clarification surface (RFC 0102 / ADR 0051 bridge) and folds the participant's answer into the pending command's single unfilled slot; with no clarification or no suspend it passes the revision through unchanged, bounded to one round. v1.22.0 closes the NODE-PACK-AUDIT NP-KT-1 surface-parity sweep: 17 thin wrappers over the family surfaces no node reached — core reads (list-challenges, get-enrollment, today, progress) + set-schedule-preference, creator reads (get-candidate, get-candidate-plan, lesson-media) + create-candidate, accountability (list-circles, coach-caseload, propose-plan-change), community (creator-profile, creator-analytics), integrations (list-consents), metrics (verifier-quality), organizations (org-catalog). Also declares the missing role:action on remind-today (NP-KT-2). v1.23.0 (XCH-KT-1): plan-generate now fetches the authoritative plan JSON schema from the creator surface (planSchema) at call time and hands it to the model as responseSchema + prompt grounding — the hand-authored shape prose survives only as the older-host fallback. v1.28.0 (ADR 0689, KickBot speaks first): kickbot-coach-turn — the reminder-loop's second node; after the consent-gated reminder it enqueues ONE proactive turn of the participant's named guide into their own 1:1 with KickBot via ctx.features.kicktodo-core.kickbotCoachTurn (gated: active enrollment, something pending, not muted; idempotent per enrollment per local day). Skips honestly on an older host without the op.

# ADR 0624 — Profiles: an honest `get` node, lifecycle host events, completeness guidance on the wire, and erasure that reaches peers' rows

Status: implemented (2026-09-02 — see § Implementation record; feature loop 2026-09, iteration 3 — User Profiles; closes `UPWF-1`, `UPWF-2`, `UPWF-3` from `WORKFLOWS-ASSESSMENT.md`, `PROF-8`, `PROF-9`, `PROF-10` from `CODEBASE-ASSESSMENT.md`, and the backend half of `PROF-UX-14` from `UX-ASSESSMENT.md`, all dated 2026-09-02)

Extends ADR 0005 (User Profiles) and ADR 0023 (agent pinning — untouched: a UI preference, not orchestration); composes ADR 0208 §1 (host-event bindings), ADR 0617 / ADR 0622 (the lifecycle-event shape, the `{ silent }` seed lane, the transition guard), ADR 0464 (subject erasure), ADR 0525 (pack schema ids), ADR 0555/0572 (steward manifest + side-effect floor). ADR 0042 (profile knowledge, HOME-tenant by design) is composed read-only and NOT widened — see § Boundaries. Host work only — no wire change.

## Context

The 2026-09-02 `/grade-workflows` pass demoted the feature from A+ to B+ on one runtime-verified Blocker: **`feature.profiles.nodes.get` has returned `{ status: 'success', outputs: { profile: null } }` for every input since it shipped (#1935, 2026-07-16).** `packs/feature.profiles.nodes/index.mjs:22` sends `{ profileId }`; `features/profiles/surface.ts:32` reads `str(args.userId)`; `host/featureSurfaces.ts:87` coerces the absent key to `''`; `getProfile(tenantId, '')` is a store miss; the node reports success. The surface is correct and tested (`test/team-portfolio-kb.test.ts:116-118` calls it with `{ userId }`); the pack is wrong and untested (`grep -rl feature.profiles.nodes test/` → 0). This is the CLAUDE.md non-negotiable "invalid model/node output is a typed failure, never success-with-empty" on the workflow lane, and the `mechanism-vs-wiring-must-be-tested-separately` class: the prior A+, `NODE-PACK-AUDIT.md` and the `NP-STALE-PROFILES-1` closure all graded the mechanism and never traced the argument across the pack→surface edge.

The same pass, and the two before it (ADR 0617, ADR 0622), established the loop's shape: a lifecycle feature must expose the seams a chain binds to. Profiles owns nine transitions (created, updated, avatar/portfolio set, skills replaced, endorsement given/removed, completeness crossed, pinned/unpinned, knowledge bound) and emits zero host events; `hostEventCatalog.ts` has nothing profile-shaped. "Endorsement received → notify the endorsee" and "completeness below N → nudge" are exactly a chain's job and cannot be authored by a tenant today.

The `/grade-code` pass added two defects: `PROF-8` — `setEndorsement` writes the endorser's `userId` into the TARGET's row (`profilesService.ts:581-583`) and nothing ever strips it, so an erased subject's id survives in every peer's `skills[].endorsements` (the ADR 0464 ratchet is keyed on the subject's OWN row and cannot see the embedding) and departed endorsers inflate counts forever; `PROF-9` — the endorse route decodes an already-decoded param (`routes.ts:376`), so a legal skill name containing `%` throws `URIError` → `500`. And `PROF-10`: the 13th pin silently evicts the oldest (`:268`) with a 200 while the portfolio cap in the same file is an honest 409.

The `/grade-ux` pass's one item needing backend work, `PROF-UX-14`: the completeness meter says "62%" with no "what next", because the weights (`computeCompleteness`, `:157-169`) are server-side and not on the wire.

## Decision

> **REVIEW CORRECTIONS (2026-09-02, `/architect` pre-implementation pass — 2 Blockers, 10 Shoulds folded; the review RAN 6 baseline suites (196 tests) and reproduced the Express double-decode live).** The first draft (a) would have emitted `profile.updated` + `completeness.crossed` for an avatar/portfolio write that is then UNWOUND and answered 404 (`setAvatarToken` CAS-commits the reference first, `profilesService.ts:428-446`); (b) claimed the surface passes `completenessMissing` through when `surface.ts:19-23` never calls `viewProfile`, and would have put "Alice lacks a bio" on the `/team` wire for every member; (c) said "changed only" for writers that never return `'unchanged'`; (d) let one write cross two thresholds with a single un-filterable event; (e) claimed a typed refusal on the run lane when the executor maps any `OpenwopError` to `internal_error`; (f) overstated the corpus parity scan (46 spread call sites are undecidable by a literal-key scan) and the erasure reach (erasing tenant only); (g) used `pin_limit`, which is not an `OpenwopErrorCode`. All corrected below; the review is the record.

**D1 — The `get` node becomes honest, on BOTH halves.** (1) `index.mjs` sends `{ userId: inputs.userId }`; `pack.json` documents `Inputs: { userId }`. (2) `surface.getProfile` REFUSES an empty id with a typed `validation_error` — on the run lane this is a node **FAILURE** (`status:'failure'`; `ensure()`/`get` in `index.mjs:20-24` do not catch), recorded by the executor as `internal_error` (`executor/executor.ts:1057-1076` surfaces `.code` only for provider/MCP/replay errors — a scoped core decision to allowlist `OpenwopError`'s closed code union is filed as a follow-on, not made here); the witness asserts `status:'failure'` + the message. (3) A real-id miss is an EXPLICIT empty, never an implicit one: `get.output.json` gains `found: boolean` (required) beside `profile: object|null`, so a chain branches on `{ falsy found }` (a typed `not_found` would fail the run un-branchably; the surface corpus is split 14 throw / 19 null — the flag is the honest read shape). (4) Schemas `get.input.json` / `get.output.json` / `list.output.json` with ADR 0525 `$id`s at `/1.1.0/`. (5) Pack 1.0.0 → **1.1.0**, `feature.ts:22` in lockstep (no toggle `ref.kind:'node'` binding touches profiles); steward digest + side-effect floor regenerated; **registry republish owed**. No other consumer sends `profileId` (grepped). Replay: reads stay `role:"action"`.

**D2 — The witness, scoped honestly.** `test/profiles-node-through-surface.test.ts` runs BOTH pack nodes against the REAL `buildProfilesSurface` on a seeded tenant: `get { userId }` → a non-null projected profile with `found:true`; unknown id → `found:false, profile:null`; no `userId` → `status:'failure'`; `list` → the roster. Findings in other features are filed per feature, not fixed here.

## Boundaries audit

- Route collision: none — no new HTTP route; `completenessMissing` is a new field on existing responses.
- Concept duplication: the event seam is `hostEventDispatcher` (ONE); the weights table becomes ONE constant read by two functions; the erasure strip lives in the existing registered eraser. No new store.
- **ADR 0042 is composed, not changed.** Profile rows and knowledge bindings stay home-tenant-keyed (`profilesService.ts:122,187-198`); the prune-on-read guard (`host/knowledgeBindingPrune.ts`) is untouched; `PROF-11(d)` adds the `ws:`-workspace pin so a future "obvious" widening turns a test red before it reaches the prune.
- Helper reuse: `features/users/emit.ts` shape; `users/surface.ts` typed-refusal shape; `unpinAgentsForTenant` CAS-scan shape; `appendAudit` ids-only shape.
- Capability honesty: nothing at `/.well-known/openwop` changes. Toggle: none (always-on).
- Replay/fork: read nodes stay `action`; no side-effect node is added (the feature's writes are self-service, not chain verbs — an "endorse" node would let a run write another user's row on the endorser's behalf and is deliberately NOT shipped).

## RFC verdict

**Host-extension — no RFC.** `host.*` events are the host's namespace (RFC 0086 §E); the pack rides the Accepted RFC 0013 format; `completenessMissing` is a `/v1/host/openwop-app/*` field.

## Alternatives weighed

1. **Fix only the pack's key name.** Rejected: the surface returning `null` for `''` is the half that let the drift ship green; both halves close, and D2 makes the class visible corpus-wide.
2. **A `feature.profiles.nodes.endorse` side-effect node** so a chain can endorse. Rejected: endorsing is a cross-principal write on the endorser's behalf; a run has no honest endorser. Reads only.
3. **A completeness recompute daemon / nudge timer.** Rejected: doctrine FAIL (`WF-PROF-1`); the crossing is derived inside the mutation.
4. **Emit `pinned`/`knowledge.bound`.** Rejected (ADR 0023 / ADR 0042 reasons above).
5. **Send the weights table to the SPA and compute the caption client-side.** Rejected: two copies of a product judgment drift; the server derives, the client renders.

### Deviations from the Decision (recorded, not silently edited)

1. **D1 (3) — the node FORWARDS the typed refusal instead of letting it escape.** `index.mjs` `get` catches an error whose `code` is `validation_error` and returns `{ status: 'failure', error: { code, message } }` — the `feature.crm.nodes` shape the executor already passes through verbatim (`executor.ts:1233`). The ADR said "`ensure()`/`get` do not catch … recorded as `internal_error`" and filed an executor allowlist follow-on; with this shape the surface's own code reaches the run for THIS pack without that core change. The follow-on stays open for surfaces whose nodes let the throw escape.
2. **D2 — the scan found NO siblings.** 60 packs × 68 surfaces × 366 methods; population {literalNoSpread 279, spread 91, nonLiteral 19} call sites, {readable 355, opaque 11} methods, 270 asserted literal×readable pairs — **`knownDrift` is empty**. The ADR's "will likely find siblings of `UPWF-1`" did not materialise on the assertable population; the 110 excluded call sites and 11 opaque methods are pinned denominators, not a finding.
3. **D4 — the weights table lives in a NEW module** (`completeness.ts`), not a constant inside `profilesService.ts`: `emit.ts` needs `computeCompleteness` and `profilesService.ts` needs `emit.ts`, so the constant moved out of the cycle. `profilesService.ts` re-exports `computeCompleteness` / `completenessMissing` / `COMPLETENESS_WEIGHTS`. The field names on the wire are `avatar`, `bio`, `skills`, `jobTitle`, `department`, `availability`, `interests`, `portfolio`, `equipment`.
4. **D5 — the strip runs even when the subject has NO own row in the tenant.** An endorser never needs a materialised profile (`setEndorsement` writes the TARGET's row), so `deleteSubjectProfile` returning `false` (no own row) still strips peers. The eraser now reports `rowsTouched` (own + peers) so a matched-nothing fan-out is not reported as success.
5. **D6 — "a RAW `%` is Express's own 400" is FALSE on this host.** Express's router throws `URIError` with `status: 400` while matching the param, but the core `error-envelope` middleware does not honour `err.status`, so the refusal surfaces as **500** today (reproduced in `profiles-adr0624-routes.test.ts`, asserted as `>= 400`). The legal-name case (`encodeURIComponent('50% off')` → 200) is what PROF-9 was about and is fixed. Core follow-on: map an Express `URIError`/`err.status` to its own status in the envelope — filed as **`CORE-ENV-1`** in `docs/steward/CODEBASE-ASSESSMENT.md` (§ Cross-Cutting — Config / Deploy Defaults; also covers body-parser's `entity.parse.failed` 400 and `entity.too.large` 413, which the same branch swallows).
6. **D6 — the pin-cap `details` carry `{ maxPinned: 12, target }`** (which pin lane was full), one key more than the portfolio cap's `{ maxPortfolio }`.
7. **D7 — the endorse audit row is written on the CAS-WON transition ONLY.** `setEndorsement` returns `{ profile, changed }` and the route appends `profiles.endorsement.given|removed` only when `changed` is true — the same gate as the host event. (An earlier shape audited every non-404 attempt, so an idempotent re-remove wrote a `removed` row for nothing removed — and `profiles-adr0624-routes.test.ts` pinned that as three rows. Review S1 flipped both: the test now asserts NO row on the idempotent attempt.)
8. **Registry republish of `feature.profiles.nodes` 1.1.0 is still owed** (the `chain-pack-fix-needs-registry-republish` class).

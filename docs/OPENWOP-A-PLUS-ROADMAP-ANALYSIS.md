## 1. Bottom line

1. **The roadmap's residue is largely right; its "required work" lists are 40–60% stale, and it is now staler than at pass 1.** It was written from decision text and hand-kept ledgers. Its app baseline predates 0554 P3 (#3322), H49 (#3323), H51 (#3324) and 0553 P3 (#3325); several bullets were stale at authoring (H44, 0555 P2, 0556 P2 are ancestors of the baseline). An agent following it verbatim would rebuild the compensation operator panel, the SLO projection, the host-call broker, the MCP downgrade floor, and the confused-deputy tests.
2. **It never names the RFC 0147 §A.1 wire freeze**, which still binds: R3 and R9 are "Open — unwitnessed", R14 "Open, Critical, externally gated" (`RFCS/registers/0147-…risks.md:12,18,23`). Proposed RFCs 0158/0159/0162 are new optional wire; `compensation.md:439-442` parks G6/G7/G9 on exactly that. Each must be argued "essential/safety" or sequenced after the freeze — Phase 2 depends on all three and the plan does neither.
3. **Under the roadmap's own rule 6, only 3–4 of the 13 proposed artifacts are new decisions.** RFC 0162 (durability/DR — a real hole, with a prerequisite), a narrowed 0581 (ingestion isolation), a narrowed 0584 (the shared multi-process harness), and the bounded-execution half of 0580. 0158 ≈ 85% RFC 0151 §E/G7/G9; 0159 ≈ 70% RFC 0150 §D; 0160 = RFC 0154 §E/UQ3; 0161 is v2 work already decided in principle; 0163's premise is false (fakes ≠ independent is already normative); 0164 = RFC 0149 §D + the two existing generators; 0582 = ADR 0549's own recorded residual; 0583 ≈ 50% exists under 0550; 0585 duplicates RFC 0156 §C + `SECURITY/external-audit-engagement.md`.
4. **This pass found real defects the roadmap does not name — three of them wire-visible on an advertised family, none needing an RFC:**
   - `compensationStatus` reads **`pending` on every successfully completed run** that ran a compensator-declaring node (obligations mint `requested` at forward commit; the fold maps all-`requested` → `pending`; `GET /v1/runs` projects it unfiltered) — `compensation.md` §D says `none`. Found independently by two slices, re-verified by the orchestrator. No corpus leg covers a healthy run.
   - The unwind **invokes the inverse from the live workflow definition** (`collectDeclarations` at unwind time), not from the recorded plan; the row's mint-time `compensationNodeTypeId/compensationInput` are only reported — the case `compensation.md:212-215` forbids.
   - Operator `start` (host-ext) has **no run-state gate and bypasses `policyAdmitsTrigger`** — an admin can fire an inverse against a running or healthy completed run; RBAC-gated, so P2.
   - Duplicate run admission across a crash between the run+outbox commit and the ledger complete (two executing runs; client learns of the second); the CAS boolean is ignored; the same window exists in `userAgents.ts`; the production Postgres ledger SQL runs in **no lane** (pg-mem substitutes a hand-written double).
   - MCP client cache `scopeFingerprint` carries **no authorization material** and `invalidateMcpCacheForPrincipal` has **zero production callers** — H53 (#3325) did not change this and is now LIVE (deploy #5); ADR 0553 `:290` claims the opposite while `cacheable-lists` is advertised on the wire.
   - `unpdf@1.6.2` vendors pdf.js 5.6.205 invisibly to `npm audit`; **no upstream fix exists** for unpdf/officeparser/image-size today; and `check-audit.mjs:93` auto-waives any NEW advisory on an already-excepted package.
   - Registry pack signatures cover **`pack.json` only** (158/160 versions): prompts and schemas in the tarball are unsigned; the tarball digest lives in the unsigned manifest; the app installer mirrors this. No app ADR owns the registry.
5. **Six gates that cannot fail (plus five from pass 1) hide inside the plan or the tree**, e.g. `docs/PROTOCOL-STATUS.md`'s "Reference Host Conformance Evidence" table has rendered **empty since 2026-06-11** because a padded header stopped matching the generator's `startsWith` — `--check` stayed green; the spec repo's **Conformance Soak is 100/100 failures back to 2026-08-09** on the in-memory host's WCP2 expansion drift, and because that guard is step 4 the strict suite and the corpus's ONLY durability witness (`staleClaim`/`restart-during-run`) have not executed since; the corpus's `mcp-cache-tenant-scope` leg has three silent-pass paths and its deployed-wire "1/1, two credentials" witness was one shape assertion.
6. **Two pass-1 "external blockers" are not external:** `@a2a-js/sdk@1.0.1` (npm, 2026-07-28) ships client + Express/gRPC server + 0.3 compat, and Python `mcp==2.0.0` (PyPI, 2026-07-28) implements revision 2026-07-28 (`server/discover`, `Mcp-Method`, `requestState` — verified in the unpacked wheel; the TS SDK 1.30.0 tops out at 2025-11-25). Both official-peer runs are corpus decisions, not waits.
7. **What actually blocks A+ is human**, as Part VI says: two (really three-org, per the WG charter) independent maintainers; the external audit (outreach never sent; `openwop-app` not in scope); a Tier-3 host; hosted-CI billing + branch protection (app `main` unprotected, PRs #3321–#3325 0 checks / 0 reviews); a runtime decision for pack network denial; a second region and an OTLP collector.
